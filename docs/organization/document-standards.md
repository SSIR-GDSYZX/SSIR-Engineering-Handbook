# 文档规范

本规范适用于手册中的教程、技术说明、项目记录和实验报告。优先使用已有[标准模板](../templates/index.md)，避免另建平行格式。

## 标题与文件组织

- 每篇文档只使用一个一级标题（`#`）作为页面主标题；章节依次使用 `##`、`###`，不要跳过层级。
- 新文件名和目录名使用小写英文、数字及连字符（kebab-case），避免空格和含糊缩写。分类目录的首页使用 `index.md`；文件名应简洁描述主题。
- 新增页面时同步更新 `mkdocs.yml` 导航，并检查文内链接和导航都指向实际存在的 Markdown 文件。不要为改名而改动已有稳定路径。

## 元数据

每篇文档应在文件开头使用以下 YAML 元数据。`last_reviewed` 使用 ISO 日期格式；尚未审核时保留 `YYYY-MM-DD` 占位符，并保持 `status: draft`。

```yaml
---
title: Document Title
category: General
status: draft
owner: SSIR
last_reviewed: YYYY-MM-DD
---
```

状态只能使用：

- `draft`：草稿，尚未完成审核。
- `review`：正在审核。
- `approved`：已由适当负责人审核批准。

模板示例中的字段值和方括号内容均需按实际情况替换；示例不代表真实组织资料。

## Markdown、图片与链接

- 使用标准 Markdown；代码围栏必须标注语言，例如标记为 `python`、`powershell` 或 `text`。
- 图片放在 `docs/static/images/`，示意图放在 `docs/static/diagrams/`。附件也应放入合适的 `docs/static/` 子目录，并使用相对当前文档位置的相对路径链接。
- 图片添加简短替代文本；优先使用清晰的实际截图或技术示意图。不得上传包含个人信息、访问凭据或未经授权资料的截图。链接文字应描述目标内容。移动或重命名文件后检查所有引用。
- 公式使用 LaTeX：行内写作 `\(a^2 + b^2 = c^2\)`，独立公式使用 `\[...\]`。
- 流程图使用 Mermaid 代码围栏，并确认图表语法可读、内容不包含内部流程或敏感信息。

## 引用与维护

- 使用清晰、可移植的 Markdown，避免把正文绑定到特定主题的短代码。
- 说明适用的软件/硬件版本、单位、环境、复现步骤、限制及最后验证日期。
- 引用外部资料时，提供有意义的标题和原始来源链接；必要时注明作者、版本或访问日期，并尊重原资料许可证。避免复制大段受版权保护内容。
- 仅使用已获准发布且许可允许的图片、论文摘录及其他材料；不确定授权范围时先咨询维护者，不要直接复制受版权保护内容。
- 不编造组织信息、设备型号、人员或项目数据。
- 发布前确认公开范围；不提交个人资料、内部资产清单、采购信息、访问凭据或未获授权的数据。
- 安全及操作类内容必须由适当负责人审核；获得审核前保持 `draft` 或 `review`，不得标记为 `approved`。
- 如适用，记录复核日期；内容发生重大变化时重新审核。
